# Reports

Generated by `ragtrail eval --dataset <wixqa|qasper> report` (see `docs/datasets.md`). Numbers from 2026-10-30/31.
Agent: Haiku via `claude -p`. Judge: Sonnet via `claude -p`, blind to the arm (no API spend).

## Full runs — repeat traffic, lexical + embedding matcher

The intended use case: the same question asked again in other words. The original questions warm the cache with
oracle trails (they cite the gold articles or evidence sections, as a verified answer would); the test set is one
Haiku paraphrase of each. Both arms use the same model, tools, prompt and call cap; only the trail store differs.

| Dataset | n | Tool calls cold → warm | Input tokens cold → warm | Seconds | Judged correct cold → warm (95% CI of Δ) | Sign test |
|---|---|---|---|---|---|---|
| WixQA help center (short articles) | 200 | 3.40 → 2.22 (−35%) | 15.0k → 10.8k (−28%) | 12.1 → 10.8 | 69.8% → **86.2%** (+16.5, +11.5 to +21.2) | 68 vs 13, p < 0.001 |
| QASPER papers (long, sectioned) | 400 | 4.08 → 1.48 (−64%) | 21.4k → 9.2k (−57%) | 12.5 → 9.7 | 60.8% → **71.6%** (+10.9, +7.2 to +14.4) | 84 vs 25, p < 0.001 |

- The warm agent saw the gold article or evidence section more often: WixQA 72% → 98%, QASPER 82.5% → 100%.
- Savings grow with the cost of orientation: on long papers the cold agent searches and reads ~3 times; the warm
  agent mostly answers from the prefetched evidence.
- Judge check: on 40 random WixQA answers labelled blind in-session (by the session model, not a human),
  Sonnet agreed exactly on 32 and within one grade on all 40; it is slightly stricter.

## Without oracle: trails the agent recorded itself (WixQA, n = 200)

Phase A: the agent answers the 200 original questions with an empty cache and calls `record` with the nodes it
chose to cite (it self-approves every answer: no external signal). Phase B: the paraphrases run against that cache.
The cold arm is the same as above.

| | Cold | Warm, self-recorded trails | Δ (95% CI) |
|---|---|---|---|
| Tool calls | 3.40 | 2.08 | −1.31 (−1.55 to −1.07) |
| Input tokens | 15.0k | 10.0k | −33% |
| Judged correct | 69.8% | 74.2% | +4.5 (−0.8 to +9.8), sign test p = 0.10 |

- Savings hold without oracle trails; accuracy does not drop (the gain is not significant).
- Self-recorded trails are worse evidence: 135/200 cite a gold article (oracle: 200/200), and 69% of recalled paths
  hold one.
- **Wrong trails propagate errors.** Split by how the phase-A answer was judged:

| Phase-A answer | n | Cold | Warm |
|---|---|---|---|
| correct | 117 | 79% | 87% |
| partial | 62 | 60% | 69% |
| incorrect | 21 | 50% | **21%** |

  The admission rule (record only with a positive outcome signal) is what makes the cache safe; here every answer
  was self-approved. The oracle results above are an upper bound on the per-hit benefit.

## Gated: only trails from answers judged correct (WixQA, n = 200)

Same phase A as above, but a trail is admitted only if its answer was judged correct (116 of 200), standing in for
explicit user feedback. The judge sees the reference answer, so this is an ideal gate. Same cold arm.

| | Cold | Warm, self-recorded | Warm, gated |
|---|---|---|---|
| Recall fires (offline) | — | 178/200, 69% hold gold | 115/200, 78% hold gold |
| Tool calls | 3.40 | 2.08 | 2.52 (−0.87, CI −1.07 to −0.67) |
| Input tokens | 15.0k | 10.0k | 11.6k (−22%) |
| Judged correct | 69.8% | 74.2% (+4.5, CI −0.8 to +9.8) | **75.5%** (+5.8, CI **+1.0 to +10.8**) |

| Phase-A answer | n | Cold | Warm, self-recorded | Warm, gated |
|---|---|---|---|---|
| correct | 117 | 79% | 87% | 91% |
| partial | 62 | 60% | 69% | 59% (no trail) |
| incorrect | 21 | 50% | **21%** | 40% (20 of 21 got no trail) |

- Gating removes the harm: the questions whose first answer was wrong no longer receive that wrong path. Their
  50% → 40% comes from runs that missed in the warm arm, so it is run-to-run noise, not cache damage.
- The price is coverage: fewer hits, so savings fall from −1.31 to −0.87 calls per question. Accuracy is the first
  significant gain without oracle trails.
- Partial answers were excluded by this gate; with self-recording they still helped (60% → 69%).

## Reference-free gate (WixQA, n = 200)

Same phase A and cold arm as above, but the gate never sees the reference answer. A verifier (Haiku via `claude -p`) is
shown the question, the phase-A answer and the current text of the nodes it cited, and a trail is admitted only if it
says the answer is supported by them (134 of 200). This is a gate a deployment could run.

| | Cold | Warm, self-recorded | Warm, ideal gate | Warm, reference-free gate |
|---|---|---|---|---|
| Recall fires (offline) | — | 178/200, 69% hold gold | 115/200, 78% hold gold | 127/200, 74% hold gold (95 prefetch, 32 hint) |
| Tool calls | 3.40 | 2.08 | 2.52 (−0.87, CI −1.07 to −0.67) | 2.40 (−1.00, CI −1.21 to −0.80) |
| Input tokens | 15.0k | 10.0k | 11.6k (−22%) | 12.5k (−17%) |
| Judged correct | 69.8% | 74.2% (+4.5, CI −0.8 to +9.8) | **75.5%** (+5.8, CI +1.0 to +10.8) | 74.0% (+4.2, CI −0.8 to +9.2), sign test p = 0.18 |

| Phase-A answer | n | Cold | Warm, self-recorded | Warm, ideal gate | Warm, reference-free gate |
|---|---|---|---|---|---|
| correct | 117 | 79% | 87% | 91% | 91% |
| partial | 62 | 60% | 69% | 59% | 58% |
| incorrect | 21 | 50% | **21%** | 40% | **29%** |

Verifier verdict against the judge's verdict on the same phase-A answer:

| Verifier | Judge: correct | Judge: partial | Judge: incorrect | Total |
|---|---|---|---|---|
| supported (admitted) | 88 | 36 | 10 | 134 |
| unsupported (rejected) | 29 | 26 | 11 | 66 |

- Savings are close to the ideal gate (−1.00 vs −0.87 calls) because the verifier admits more trails (134 vs 116).
- Accuracy is above cold but, unlike the ideal gate, the interval includes zero (−0.8 to +9.2).
- The verifier is a weak filter: 10 of 21 incorrect answers (48%) were still admitted, and 29 of 117 correct ones (25%)
  were rejected. Of the admitted trails, 66% were judged correct (88/134), against 58% across all 200 answers.
- The incorrect-first-answer group is at 29% (n = 21), between self-recorded (21%) and the ideal gate (40%): the
  reference-free check removes about half of the harm, not all of it.

## Reference-free gate on QASPER (paper as scope, n = 400)

Same protocol as the WixQA gate, on long papers. Each paper is its own scope and the title is stripped before matching,
so a trail can only be recalled for the paper it was recorded on. Phase A: the agent answers the 400 original questions
with an empty cache and records the sections it cites. A verifier (Haiku, shown the question, the answer and the
current text of the cited sections, never the reference) admits a trail only if the answer is supported: 332 of 400.
Phase B runs the paraphrases. Same cold arm as above. The ungated self-recorded arm was not run on QASPER.

| | Cold | Warm, oracle trails (title in the query) | Warm, reference-free gate |
|---|---|---|---|
| Recall fires (offline) | — | 400/400 (title match) | 236/400, 85% hold gold (164 prefetch, 72 hint) |
| Tool calls | 4.08 | 1.48 | 2.96 (−1.12, CI −1.32 to −0.94) |
| Input tokens | 21.4k | 9.2k | 16.5k (−23%) |
| Seconds | 12.5 | 9.7 | 13.8 (+1.3, CI +0.7 to +1.9) |
| Judged correct | 60.8% | **71.6%** (+10.9, CI +7.2 to +14.4) | 64.1% (+3.4, CI +0.1 to +6.6), sign test p = 0.18 |

| Phase-A answer | n | Cold | Warm, reference-free gate |
|---|---|---|---|
| correct | 221 | 84% | 88% |
| partial | 73 | 51% | 57% |
| incorrect | 106 | 18% | 19% |

Verifier verdict against the judge's verdict on the same phase-A answer:

| Verifier | Judge: correct | Judge: partial | Judge: incorrect | Total |
|---|---|---|---|---|
| supported (admitted) | 201 | 55 | 76 | 332 |
| unsupported (rejected) | 20 | 18 | 30 | 68 |

- Savings hold on long papers: −27% tool calls and −23% input tokens, from the prefetch hits (163 questions in the runs), which need 1.4 calls
  instead of 3.9. The warm arm is slower in wall-clock time (+1.3 s), because misses still pay for the recall call.
- Accuracy is above cold, with a CI that just excludes zero (+0.1 to +6.6) and a sign test that does not (p = 0.18).
  Treat it as "no loss, small gain", not a significant gain.
- The verifier is permissive here: it admits 76 of 106 incorrect answers (72%; WixQA: 48%) and rejects 20 of 221
  correct ones (9%). Admitted trails were judged correct 61% of the time (201/332), against 55% over all 400.
- Wrong trails did not hurt: the incorrect-first-answer group stays at 18% → 19% (WixQA self-recorded: 50% → 21%).
  Cold accuracy on those questions is already low, so there is little to lose, and a QASPER trail only ever serves
  its own paper.

## How often the cache fires (offline, no LLM)

| Setting | Recall fires | Recalled nodes hold the gold |
|---|---|---|
| WixQA repeat, lexical only | 25/200 | 100% |
| WixQA repeat, + embeddings | 179/200 | 100% |
| WixQA repeat, + embeddings, self-recorded trails | 178/200 | 69% |
| QASPER repeat, paper as scope, + embeddings | 274/400 | 100% |
| QASPER, *other* question on a cached paper, paper as scope | 13/880 | 9 of 13 |
| QASPER, *other* question on a cached paper, title inside the query | 855/880 | 30% |
| WixQA disjoint (different splits), + embeddings | 55/200 | 47% |

- Put fixed context (document, product, customer) in `scope`, not in the matched text: with the paper title in the
  query, almost any question about that paper looked "similar" and got the wrong sections.
- The QASPER agent runs used titled matching (every paraphrase hit), so they measure the benefit **per hit** on long
  documents. With the paper as scope, about 7 in 10 paraphrases hit.

## Corpus edits and mixed traffic (offline, no LLM, embeddings on)

**Edits.** After recording, a random share of the cited nodes is edited; the repeats that hit before any edit are
replayed. A copy cache (stores cited text, TTL only, like MERMAIDS) and a pointer cache without validation would
serve the same hits, with old or silently changed text.

| Nodes edited | WixQA hits (179): copy cache serves old text | ragtrail prefetch / hint / miss | QASPER hits (274): copy cache serves old text | ragtrail prefetch / hint / miss |
|---|---|---|---|---|
| 5% | 11 (6%) | 99 / 80 / 0 | 20 (7%) | 176 / 93 / 5 |
| 10% | 21 (12%) | 91 / 82 / 6 | 41 (15%) | 163 / 97 / 14 |
| 25% | 49 (27%) | 74 / 76 / 29 | 94 (34%) | 122 / 108 / 44 |
| 50% | 91 (51%) | 50 / 63 / 66 | 177 (65%) | 65 / 103 / 106 |

ragtrail served a changed node 0 times at every rate; the price is fewer full prefetches.

**Mixed traffic.** Empty cache; first-time questions interleaved with paraphrased repeats; every answer records an
oracle trail. "Sibling" = another question about a paper that already has trails (it should miss).

| Dataset | Repeat rate | Questions | Recall fires | Of which without gold (false hits) | Repeats that hit |
|---|---|---|---|---|---|
| WixQA | 10% | 444 | 18% | 16 (3.6% of all questions) | 86% |
| WixQA | 30% | 571 | 34% | 18 (3.2%) | 88% |
| WixQA | 40% | 500 | 41% | 13 (2.6%) | 90% |
| QASPER | 10% | 1,422 | 9% | 8 (0.6%) | 73% |
| QASPER | 20% | 1,600 | 16% | 8 (0.5%) | 71% |

- Firing tracks the repeat rate; false hits stay at 1–4% of traffic. On WixQA, first-time questions also fire 11% of
  the time, and 6 in 10 of those reuse a gold article (legitimate cross-question reuse).
- Lexical-only matching fires far less (WixQA 7–8%, QASPER 4–8%) with similar false-hit rates.
- QASPER cannot exceed ~24% repeats with one paraphrase per question; the 30–40% rows drop sibling questions.

Details: [robustness.md](robustness.md).

## Limits

- Paraphrases are model-written, and every test question is a repeat; real traffic repeats far less (search logs:
  30–40%), so savings apply per hit. The oracle runs overstate accuracy; the self-recorded run is the realistic one.
- The judge (Sonnet) is in the same family as the agent and was checked on only 40 labels.
- Disjoint questions (different WixQA splits) barely repeat; the 20-question pilots there showed no accuracy change
  but have wide CIs (see `wixqa-eval.md`).
- No agent-level comparison against other methods yet (APC, answer caching); the edit test compares cache designs
  offline, assuming identical matching.
