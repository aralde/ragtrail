# Decisions

One line per decision: date — decision — reason.

- 2026-10-29 — `ragtrail` is free on PyPI (checked 2026-10-29) — keep the name.
- 2026-10-29 — Models are frozen pydantic models with `extra="forbid"` — immutable values are safe to share, and an accidental `answer` field fails loudly.
- 2026-10-29 — `Trajectory` gains `stale: bool = False`; `id` defaults to a uuid4 hex — `mark_stale` needs a representation; ids are generated where trajectories are built.
- 2026-10-29 — `scope` and `id` must be non-empty and must not contain `#`; datetimes must be timezone-aware and `expires_at > created_at` — `#` is the key separator, so this is what keeps scopes from colliding.
- 2026-10-29 — `put(trajectory, band_keys)` takes full band keys from the caller; the store checks each one is a band key of the trajectory's scope — the store stays independent of `MatchConfig`, and scope isolation is enforced at the storage boundary.
- 2026-10-29 — `candidates` raises `ValueError` on a band key outside `scope` instead of ignoring it — a cross-scope lookup is a caller bug and should be loud.
- 2026-10-29 — Stale trajectories are excluded from `candidates` but still returned by `get` — recall never reuses them, debugging still can see them.
- 2026-10-29 — A trajectory is expired when `expires_at <= now`; `get`, `candidates` and `incr_hits` ignore expired items even before `purge_expired` runs — mirrors DynamoDB/Cosmos, whose native TTL deletes lazily.
- 2026-10-29 — Band buckets keep the newest `band_cap` entries (default 32) by `created_at`; older entries are dropped on `put` — bounded reads per band, matching the capped list item in DynamoDB/Cosmos.
- 2026-10-29 — Stores take an injectable `clock` — TTL tests run without sleeping.
- 2026-10-29 — `SQLiteStore` keeps `hits` and `stale` as columns that override the stored JSON — counters update in place without rewriting the document.
- 2026-10-29 — Store tests are written against the `TrajectoryStore` protocol with a parametrized `store` fixture — cloud backends (M6/M7) reuse the same suite against their fakes.
- 2026-10-29 — Docstring examples run as doctests (`--doctest-modules`) — keeps the "every public function has an example" rule honest.
- 2026-10-29 — Normalization strips accents by default (`keep_accents=False`) and drops built-in en+es stopwords; question words are not stopwords; if every word is a stopword the words are kept — "cómo"/"como" should match, "how"/"why" should not, and a query never normalizes to nothing.
- 2026-10-29 — Punctuation, symbols, separators and control chars (Unicode categories P/S/Z/C) become spaces; digits stay — "rate-limit" and "rate limit" match; "v2" stays meaningful.
- 2026-10-29 — Shingles: word 2-grams (`w:`) + char 4-grams (`c:`) over the normalized text; texts shorter than an n-gram contribute themselves — short queries ("delete account") still get a signature.
- 2026-10-29 — MinHash uses blake2b-64 shingle hashes and universal hashing `(a·x + b) mod (2^61 − 1)` with `a, b` from `random.Random(seed)` — stdlib only, identical across processes and Python versions (no `hash()` randomization); values fit a signed 64-bit int for DynamoDB/Cosmos.
- 2026-10-29 — Default LSH layout is 42 bands × 3 rows (126 perms) instead of the planned 32 × 4 — on `tests/fixtures/paraphrases.json`, 32×4 surfaced 31/36 paraphrase pairs as candidates (P(collide | s=0.35) = 0.38); 42×3 surfaces 36/36 with 2/594 unrelated collisions; 64×2 also 36/36 but 18/594 unrelated (more reads). Paraphrase similarity ≥ 0.35, unrelated ≤ 0.10.
- 2026-10-29 — Thresholds live in `MatchConfig`: `prefetch_threshold=0.5`, `hint_threshold=0.25` (hint must be ≤ prefetch) — sit between the fixture's unrelated max (0.10) and paraphrase median (0.58); to be retuned with M5's eval.
- 2026-10-29 — An empty normalized query cannot be signed (`ValueError`) — callers treat it as a miss / refuse to record rather than letting all empty queries collide.
- 2026-10-29 — Band hash is blake2b-64 hex of the band's comma-joined rows — short, stable store keys.
- 2026-10-29 — `NodeResolver` gains `label(node_id) -> str` (breadcrumb) next to `content_hash` and `read`; `content_hash` returns `None` for a deleted node, which counts as changed — the recall contract shows breadcrumbs in hint mode without reading node text; `GenericResolver` defaults the label to the id.
- 2026-10-29 — `text_hash(text)` = first 16 hex chars of sha256 is offered as the default hash helper — short, stable, stdlib.
- 2026-10-29 — Admission also requires a non-empty normalized query and at least one cited node that still resolves; `useful` = cited nodes in citation order with their hash at commit time — a trajectory with nothing to hand back is useless; hashing at commit pins what the answer actually saw.
- 2026-10-29 — Steps are stored as given (tool, args, returned ids); keeping answers out of `args` is the caller's job — ragtrail never receives the answer text in its API.
- 2026-10-29 — Every admitted turn writes a new trajectory, including turns served by a recall hit — new phrasings widen coverage; dedup/merge is deferred until the M5 eval shows store growth matters.
- 2026-10-29 — Ranking: estimated Jaccard desc, then hits desc, then newest; recall walks the ranked list above `hint_threshold` and uses the first trajectory with any still-valid node, marking fully changed ones stale on the way — one dead trajectory does not hide a good older one.
- 2026-10-29 — A miss reports the best candidate's similarity (0.0 if none) — useful for tuning thresholds; `rendered` is empty on a miss so the agent sees nothing.
- 2026-10-29 — Budget: header and footer are always kept; prefetch adds whole node texts in citation order while they fit, lists the rest as one-line refs, and collapses overflow into `(+N more nodes)`; a prefetch where no node text fits is returned as `hint` — never cut a node mid-text; the mode tells the truth about what was included.
- 2026-10-29 — Default `budget_tokens` is 1500, tokens estimated as `ceil(chars / 4)` (pluggable `estimator`) — enough for 2–4 typical sections; no tokenizer dependency in core.
- 2026-10-29 — `recall` increments `hits` on every non-miss — gives ranking and eval a usage signal.
- 2026-10-29 — `turn(...)` recalls on entry and commits on exit; the outcome is set with `t.accept(...)` or `t.outcome`; an exception inside the block drops the turn and propagates — success must be explicit (admission policy), and a failed turn never leaves a trail.
- 2026-10-29 — No `ragtrail[subforest]` extra for now: subforest is not on PyPI and its repo is private, so CI cannot install it. `ragtrail.subforest.SubforestResolver` is typed against a three-method protocol (`get_node`, `ancestors`, `doc_text`) and never imports subforest; CI tests it with a fake tree, and the real-subforest tests and example run locally with `uv run --with-editable ../subforest pytest` (skipped otherwise). Add the extra when subforest is published.
- 2026-10-29 — `SubforestResolver` hashes a node's whole span (subsections included) from the stored doc text, labels skip the `site` node, and dirs/sites have no hash (cannot be cited) — editing a subsection invalidates trails that used its parent, since the agent read that text.
- 2026-10-29 — Examples share a small Markdown corpus in `examples/corpus/` (fictional "Larch" docs); `chunk_rag.py` uses paragraph chunk ids (`c1`…), `subforest_rag.py` uses subforest ids (`n7`…); `tests/test_examples.py` runs both offline — one corpus for both index styles, and the examples cannot rot.
- 2026-10-29 — The MCP server is bound to one scope (`--scope`, default `default`); tools take no scope argument — deviates from the plan's `recall(query, scope?)`: letting the model pick a scope would let it read another tenant's trails, and enforcing permissions is the caller's job, done by choosing which server a client gets.
- 2026-10-29 — The server needs an index to validate hashes: `--subforest corpus.db` (built-in) or `--resolver module:factory` (any `NodeResolver`); with neither it runs **unverified** (every node counts as unchanged, recall capped at `hint` with a note to read the nodes) — the MCP process cannot see an arbitrary RAG index; unverified still saves the orientation calls, while TTL bounds staleness.
- 2026-10-29 — `recall(..., allow_prefetch=False)` caps the mode at `hint` — used by unverified mode; prefetching unverified text would break "validation on read".
- 2026-10-29 — `record(query, cited, outcome="accepted", steps=None)`; the outcome is declared by the caller; steps are `{tool, args, returned}` and validated as `Step` — the agent is the one that knows its answer is grounded; malformed steps return a tool error instead of raising.
- 2026-10-29 — Tool results carry the text in both `content` and `structured_content` (plus mode, similarity, nodes, stale) — same approach as subforest: some clients show only structured content.
- 2026-10-29 — Added `ragtrail purge --db` next to `serve` — SQLite has no native TTL; expired rows are already ignored on read, this reclaims space.
- 2026-10-29 — Manual smoke test with Claude Code 2.1.299 (`claude -p --mcp-config`, Haiku, `--subforest` on the examples corpus): session 1 `recall` → miss, `record` cited n3/n4 → recorded; a new session's `recall("I forgot my password, how can I reset it?")` → prefetch, similarity 0.55, nodes n3/n4, and the model answered from the prefetched text alone. Tools were listed and callable.
- 2026-10-30 — Default `hint_threshold` raised from 0.25 to 0.4, chosen on the dev pairing only (WixQA-Simulated queries vs WixQA-Synthetic, never the test split): at 0.25 only 23% of matches shared a gold article; 0.4 → 52%, 0.5 (prefetch) → 75% — the toy fixture overstated precision; real support questions share vocabulary across different intents.
- 2026-10-30 — M5 eval is a pipeline of subcommands (`ragtrail eval fetch | paraphrase | offline | agent | judge | report`) instead of one `ragtrail eval --dataset wixqa --n 200` — the LLM steps run on the user's subscription and must be resumable separately; the offline step needs no LLM at all.
- 2026-10-30 — Warm-up trails are oracle trails: each warm-up question cites its gold articles, admitted as `verified` — running an agent over 6,421 warm-up questions is not affordable; verified citations are exactly what the admission policy admits. Test questions never feed the store.
- 2026-10-30 — Two scenarios: **disjoint** (plan: warm Simulated + Synthetic, test ExpertWritten) and **repeat** (warm ExpertWritten, test one Haiku paraphrase each) — WixQA's splits never repeat a question, so disjoint alone cannot show the intended use case; repeat is reported separately with its overlap stated.
- 2026-10-30 — The eval needs subforest (corpus, docs MCP server, resolver); the SQLite-FTS5 fallback retriever from the plan is deferred — subforest is the sibling project and already ships the WixQA builder; the eval runs locally where subforest is installed. `ragtrail.eval` imports subforest lazily and mypy ignores it when missing.
- 2026-10-30 — Agent arms share tools (subforest docs server in chunks view + recall-only ragtrail server), prompt, model and call cap; `cold` gets an empty trail store, `warm` a fresh copy of the warm store per run — the only difference is the store, and runs never feed each other.
- 2026-10-30 — Agent pilots are stratified ("matched first"): every question whose offline warm recall was not a miss, filled up with seeded random misses — a random sample would be ~90% misses in both scenarios and measure nothing; the report states the stratification, and the population effect is hit rate × per-hit effect.
- 2026-10-30 — Accuracy: LLM judge (Haiku, prompt in `ragtrail/eval/judge.py`), blind to the arm (opaque keys, shuffled batches), correct/partial/incorrect → 1/0.5/0; token F1 against the reference is reported alongside — no paid API; the judge is the same small model, so its verdicts are a pilot signal, not ground truth.
- 2026-10-30 — `ragtrail serve` gained `--log` (one JSON line per call) and `--no-record` (recall-only) — the eval counts recall calls and keeps the warm store fixed.
- 2026-10-30 — Models rephrase the question into keywords before calling `recall`, which breaks lexical matching (seen in the first eval runs). The MCP instructions and the `recall` tool description now ask for the user's question verbatim — matching works on the original wording; the Python middleware is unaffected since it receives the real query.
- 2026-10-30 — Finding: lexical MinHash matching has high precision but low recall on real paraphrases. Repeat scenario: 25/200 paraphrases matched (6 prefetch, 19 hint), 100% pointing at a gold article; median paraphrase-to-source similarity is 0.27, where dev precision is ~23%. No single lexical threshold serves both; the embedding matcher (`ragtrail[embed]`, "Later" in the plan) is the lever for coverage.
- 2026-10-30 — Pilot results (Haiku via `claude -p`, judged by Haiku): repeat scenario, n = 30 stratified: tool calls −0.70 (CI −1.27 to −0.17), input tokens −23%, judge accuracy +15.0 points (CI +1.7 to +28.3, sign test p = 0.11). Disjoint, n = 20: no measurable effect (accuracy −2.5, CI −12.5 to +7.5). Same-condition misses moved 78% → 61% in disjoint: with n ≈ 20, run-to-run noise is ~±15 points. Next lever: an embedding matcher for coverage; then a larger run before any headline claim.
- 2026-10-30 — Embedding matcher shipped as `ragtrail[embed]` (fastembed, `BAAI/bge-small-en-v1.5`, local CPU, no API) — M5 showed lexical recall was the bottleneck; on WixQA paraphrases bge-small puts the own-source cosine at median 0.94 vs MinHash Jaccard 0.27.
- 2026-10-30 — Embeddings are indexed with SimHash LSH (seeded Gaussian hyperplanes generated with stdlib `random`, 30 bands × 16 bits) under the same `b#scope#idx#hash` keys, band indices from 100 — keeps "lookup = key reads, no vector DB" for every backend. Same-domain embeddings crowd buckets (cosine > 0.7 is common), so wide bands are needed: with the store's 32-per-bucket cap, 30×16 found 178/179 repeat and 48/54 disjoint true matches with a median of 22 / 325 candidates; 18×16 and 24×20 lost too many.
- 2026-10-30 — Trails store the normalized query embedding (5 decimals) and `embed_model`; cosine is only computed between the same model — vectors of different models are not comparable; re-record after switching models.
- 2026-10-30 — Match rule: a candidate takes the better of its lexical level (Jaccard 0.4 / 0.5) and its embedding level (cosine 0.88 hint / 0.92 prefetch); thresholds from the dev pairing only (cosine 0.88 → 52% gold-sharing, same as lexical 0.4; 0.92 → 62%). `RecallResult.matched_by` says which one fired. A union rule did not beat either alone on dev, so there is no blended score.
- 2026-10-30 — Embed pilot results (Haiku, judged by Haiku): repeat (n = 30) −1.17 tool calls (CI −1.63 to −0.60), input tokens −30%, judge +11.7 points (CI 0 to +23.3); offline 179/200 paraphrases matched, all pointing at a gold article. Disjoint (n = 20): 55/200 matched, 47% on a gold article; agent judge 75% → 75% (CI ±17.5).
- 2026-10-31 — Full runs follow subforest's tier-3 setup: every test question in both arms (WixQA repeat: 200; QASPER repeat: 400), Haiku agent via `claude -p`, Sonnet judge via `claude -p`, blind to the arm — pilots were too small (±15-point noise). Judge files are per judge model (`judgments-<run>.<model>.json`).
- 2026-10-31 — Judge check: 40 seeded-random WixQA answers labelled blind in-session (by the session model, not a human) vs Sonnet: exact agreement 32/40, within one grade 40/40; Sonnet is slightly stricter (mean 0.79 vs 0.86). It is blind to the arm, so the strictness does not bias the cold/warm delta.
- 2026-10-31 — QASPER oracle trails cite the evidence sections, not the paper: a whole paper does not fit a prefetch budget, and a verified answer would cite where the evidence is. 88.5% of questions' evidence fits the 2,000-token recall budget.
- 2026-10-31 — Finding: shared context in the query dominates similarity. With titled QASPER questions, a *different* question about a cached paper triggered recall 85% (lexical) / 97% (embeddings) of the time, ~70% with the wrong sections. Putting the paper in the `scope` and matching the bare question fixes it: with embeddings, paraphrases still hit 274/400 (all correct) while other questions on the same paper trigger 13/880 (4 wrong). Guidance: fixed context (document, product, customer) belongs in `scope`, not in the matched text. The QASPER agent runs used titled matching, so they measure the per-hit benefit on long documents; the realistic hit rate comes from the scoped offline numbers.
- 2026-10-31 — `claude -p` reports a spent window as "You've hit your session limit · resets …"; the usage-limit detector now matches it (it was recorded as errors and retried by the driver instead of pausing).
- 2026-10-31 — Self-recorded trails (no oracle), WixQA n = 200: phase-A agent self-approved every answer (74.0% judged correct); 198/200 called `record`, 135/200 trails cite a gold article. Phase B vs the same cold arm: tool calls −1.31 (CI −1.55 to −1.07), input tokens −33%, judged 69.8% → 74.2% (+4.5, CI −0.8 to +9.8). By phase-A verdict: correct 79% → 87% (n = 117), partial 60% → 69% (n = 62), incorrect 50% → 21% (n = 21) — wrong trails propagate errors, matching Xiong et al. 2025. Headline claims now use the self-recorded numbers; oracle runs are reported as an upper bound.
- 2026-10-31 — Offline "recalled nodes hold the gold" now maps recalled sections to their document (`doc_of`) — self-recorded trails cite sections while WixQA gold is articles; without the mapping coverage read as 30% instead of 69%.
- 2026-10-31 — Related-work review (`docs/related-work/`): no surveyed work caches a cross-question agentic-RAG retrieval path with per-node hash validation and partial downgrade; every ingredient has precedent (APC, Proximity, Alici et al. SIGIR 2011, GroundedCache). MERMAIDS, APEx, MIA and Hierarchical Caching were seen only as snippets and must be read before any priority claim.
- 2026-10-31 — MERMAIDS (IEEE CISCE 2026) read in full: it reuses verified evidence tuples across questions in agentic RAG (per sub-query, FAISS cosine ≥ 0.85, TTL only; 19% of its sampled errors are cache staleness). Cross-question evidence reuse is therefore prior art; ragtrail's distinct claims are hash-validated pointers with read-time partial downgrade, whole-question path reuse via key-value LSH, permission scoping, the fixed-context finding, and the controlled (oracle vs self-recorded) evaluation.
- 2026-11-01 — Offline robustness evals (`ragtrail eval edits|stream`). Edits: with 10% of cited nodes edited, a copy cache would serve old text on 12% (WixQA) / 15% (QASPER) of hits; ragtrail served changed nodes 0 times and kept 173/179 and 260/274 hits (as hint where needed). Mixed traffic with embeddings, empty cache: recall fires roughly at the repeat rate (WixQA 18–41% for 10–40% repeats, QASPER 9–16% for 10–20%), false hits 0.5–3.6% of all questions. Edit selection is uniform over cited nodes; real edits cluster, which this does not model.
- 2026-11-01 — Gated self-trails (`repeat-gated`, WixQA n = 200): admitting only trails whose phase-A answer was judged correct (116/200; ideal feedback, the judge sees the reference) gives tool calls −0.87 (CI −1.07 to −0.67), input tokens −22%, judged 69.8% → 75.5% (+5.8, CI +1.0 to +10.8; sign test p = 0.086). The incorrect-first-answer group no longer gets wrong paths (20/21 miss). First accuracy gain without oracle trails whose CI excludes zero. Next: a gate without the reference (e.g. a support check on the cited nodes), which is what a deployment could use.
- 2026-11-03 — Reference-free gate (`repeat-verified`, WixQA n = 200, Haiku verifier, Sonnet judge): 134/200 trails admitted; tool calls −1.00 (CI −1.21 to −0.80), input tokens −17%, judged 69.8% → 74.0% (+4.2, CI −0.8 to +9.2; sign test p = 0.18). Incorrect-first-answer group 50% → 29% (self-recorded 21%, ideal gate 40%). Verifier vs judge: 10 of 21 incorrect answers admitted, 29 of 117 correct ones rejected. The gate halves the error propagation but, unlike the ideal gate, does not give an accuracy gain whose CI excludes zero.
- 2026-11-04 — E6, reference-free gate on QASPER (paper as scope, title stripped, n = 400, Haiku agent and verifier, Sonnet judge): 332/400 trails admitted (WixQA: 134/200). Tool calls 4.08 → 2.96 (−1.12, CI −1.32 to −0.94), input tokens −23%, seconds +1.3, judged 60.8% → 64.1% (+3.4, CI +0.1 to +6.6; sign test p = 0.18). The verifier admits 76/106 incorrect answers and rejects 20/221 correct ones, yet the incorrect-first-answer group is unchanged (18% → 19%). The verifier crashed on QASPER with `Argument list too long` (`SubforestResolver.read` ignores `max_tokens`, so cited nodes are whole papers, median 22 KB per item); `verify_runs` now builds size-capped batches and trims only an item that does not fit alone. WixQA prompts are unchanged.
- 2026-11-04 — E3c, verifier prompt v2 (also rejects answers saying the sources do not cover the question; Haiku verifier, Sonnet judge). WixQA (n = 200): 79/200 trails admitted (v1: 134), 0 of 21 incorrect admitted (v1: 10), 54 of 117 correct rejected (v1: 29); tool calls −0.59 (CI −0.79 to −0.39), input tokens −8%, judged 69.8% → 75.2% (+5.5, CI +0.8 to +10.2; sign test p = 0.052). QASPER (n = 400): 217/400 admitted (v1: 332), 27 of 106 incorrect admitted (v1: 76), 67 of 221 correct rejected (v1: 20); tool calls −0.71, input tokens −10%, judged 60.8% → 60.0% (−0.8, CI −3.8 to +2.4). v2 removes the wrong trails but costs coverage; it helps where wrong trails hurt (WixQA) and does not pay off where they are cheap (QASPER, v1 +3.4).
